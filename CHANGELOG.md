# Changelog

All notable changes to Decoupled Router are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 2.0.7 (2026-08-19)

### Fixed

- [#3166364](https://www.drupal.org/project/decoupled_router/issues/3166364):
  Replaced the dead `hook_path_insert()`/`hook_path_update()`/
  `hook_path_delete()` implementations with path alias entity hooks, fixing
  the fatal error when a node's alias changed. Also resolves the long-open
  duplicate
  [#3111719](https://www.drupal.org/project/decoupled_router/issues/3111719).
- [#3611685](https://www.drupal.org/project/decoupled_router/issues/3611685):
  Caught `RedirectLoopException` from the Redirect module's repository, so a
  redirect loop no longer causes a 500 response. Crediting cruno.
- [#3411402](https://www.drupal.org/project/decoupled_router/issues/3411402):
  Resolved JSON:API route matches to the entity UUID form of the URL. The
  2.0.6 refactor always passed the entity ID, which the JSON:API parameter
  converter rejects, so the `resolved` URL for a JSON:API individual path
  was a 404. Crediting thomasdik and ankitv18.
- [#3397122](https://www.drupal.org/project/decoupled_router/issues/3397122):
  Stripped the query string and fragment from the path before the router
  match, making the bare-path match explicit instead of relying on router
  internals. Both are still preserved in the resolved URL. Crediting
  vhin0210.

### Changed

- Applied drupal-extension-scaffold v4.17.0 with GitLab CI stability fixes
  for the shared runner, expanded automated test coverage across the module,
  and cleaned up the triage queue: verified and closed
  [#3355984](https://www.drupal.org/project/decoupled_router/issues/3355984),
  [#3303226](https://www.drupal.org/project/decoupled_router/issues/3303226),
  [#3491897](https://www.drupal.org/project/decoupled_router/issues/3491897),
  [#3283966](https://www.drupal.org/project/decoupled_router/issues/3283966)
  and
  [#3495182](https://www.drupal.org/project/decoupled_router/issues/3495182)
  against the current code.

## 2.0.6 (2025-09-08)

### Added

- [#3543536](https://www.drupal.org/project/decoupled_router/issues/3543536):
  Responses can resolve to relative URLs via the new
  `absolute_resolved_urls` setting.
- [#3543596](https://www.drupal.org/project/decoupled_router/issues/3543596):
  Redirects to non-content-entity paths are reported instead of dropped.

### Fixed

- [#3525939](https://www.drupal.org/project/decoupled_router/issues/3525939):
  Redirect matching delegated to the Redirect module's own
  `RedirectRepository`, replacing the hand-built entity query.
- [#3544914](https://www.drupal.org/project/decoupled_router/issues/3544914)
  and
  [#3545398](https://www.drupal.org/project/decoupled_router/issues/3545398):
  Query strings and fragments are preserved through path translation and
  redirect resolution, per RFC 7231.
- [#3543594](https://www.drupal.org/project/decoupled_router/issues/3543594):
  Redirects to URLs with query strings work with redirect query passthrough
  enabled.
- [#3116487](https://www.drupal.org/project/decoupled_router/issues/3116487):
  Entity canonical URLs can be generated by passing the entity UUID.
- [#3543879](https://www.drupal.org/project/decoupled_router/issues/3543879):
  The redirect integration services are registered conditionally.

### Changed

- [#3529124](https://www.drupal.org/project/decoupled_router/issues/3529124):
  Dropped Drupal 9 support; requires Drupal 10.1 or 11.
- [#3544876](https://www.drupal.org/project/decoupled_router/issues/3544876):
  Added a Composer conflict against Redirect versions below 1.12.
